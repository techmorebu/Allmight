PROJECT: ALLMIGHT
PHASE: 6 — EXECUTION ADAPTERS (DRY-RUN)
STATUS: COMPLETE · VERIFIED · FROZEN

Phase 6 implements the dry-run execution adapter layer for Project AllMight.
Its purpose is to transform Phase-5 execution intents into deterministic,
adapter-specific execution plans WITHOUT performing any real execution.

This phase explicitly prohibits:
- network calls
- wallet access
- transaction signing
- RPC connections
- order placement

All outputs are dry-run only and auditable.

---------------------------------------
WHAT PHASE 6 PRODUCES
---------------------------------------

Inputs (authoritative):
- outputs/phase5/{asof}/phase5_execution_intents.json

Outputs (deterministic):
- outputs/phase6/{asof}/phase6_execution_plans.json
- outputs/phase6/{asof}/phase6_audit.txt

Core guarantees:
- Same inputs + same --asof + same adapter => identical outputs
- Phase-5 allowed_modes is the HARD upper bound
- execution_policy may restrict, never enable
- No horizon mixing (last vs i60)

---------------------------------------
ARCHITECTURE OVERVIEW
---------------------------------------

1) Intent Loader
   - Consumes Phase-5 normalized intents only
   - Refuses to run if inputs are missing or malformed

2) Policy + Gating Engine
   - Resolves effective_allowed_modes
   - Produces a structured gating_chain explaining every decision

3) Adapter Layer (Dry-Run Only)
   - paper adapter (baseline)
   - cex_stub adapter (validation-only, no network)
   - Adapter selection does NOT enable execution modes

4) Plan Builder
   - Emits deterministic execution plans
   - Includes stable plan_id with schema + policy + adapter versioning

5) Trace + Audit
   - Machine-readable trace
   - Human-readable audit file
   - Full reasoning preserved

---------------------------------------
SECURITY & SAFETY INVARIANTS
---------------------------------------

- No network imports (enforced by tests)
- No execution side effects
- No implicit enablement of modes
- No Phase-4 or Phase-5 reinterpretation
- Deterministic replay guaranteed

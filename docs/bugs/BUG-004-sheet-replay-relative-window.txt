BUG ID: BUG-004
TITLE: Phase 0 Excel semantics are replay-relative, not latest-row based
STATUS: RESOLVED
PHASE: 1D
DATE: 2025-12-22


DESCRIPTION
-----------
Initial implementations incorrectly assumed Phase 0 calculations always
referenced the most recent OHLCV row.

This caused:
- Indicator drift
- Invalid historical replay
- Backtests that silently used future information


ROOT CAUSE
----------
Phase 0 Excel formulas rely on:
- Row index position
- Window-relative calculations
- INDEX(FILTER(...), COUNTA(...)) semantics

These do NOT equal “latest candle” unless explicitly aligned.


RESOLUTION
----------
Implemented a fully replay-relative architecture:

- Replay OHLCV windows sliced deterministically
- Shared Inputs computed at explicit as-of row
- Structure L0 consumes replay snapshot
- Pressure L1 consumes replay snapshot
- No implicit access to future rows


VERIFICATION
------------
- Compared last vs i60 snapshots
- Confirmed divergence in:
  - ATR
  - TrendSimple
  - Structure state
  - Pressure score
  - Volume spike gating
- Verified across BTC, ETH, XRP, XAU


IMPACT
------
This bug fundamentally changed the system architecture.

Without fixing this, all Phase 2+ logic would have been invalid.

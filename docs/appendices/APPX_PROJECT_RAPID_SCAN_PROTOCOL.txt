APPENDIX: PROJECT RAPID SCAN & ZERO-GUESS RECON PROTOCOL
=====================================================
Status: AUTHORITATIVE
As-of: 2026-01-02 00:33 UTC

This appendix defines the mandatory rapid-scan procedure for this project.
Its purpose is to eliminate guesswork for any new chat, phase, or operator.


1. THE 90-SECOND RULE
--------------------
Any competent operator must be able to determine:
- Project state
- Current phase
- Safety posture
- What is allowed vs forbidden

…in under 90 seconds.

If this appendix cannot accomplish that, the appendix must be updated.


2. CANONICAL ENTRY POINTS (READ IN THIS ORDER)
----------------------------------------------
These files define the project. Everything else is subordinate.

1) docs/phase*/PHASE*_HANDOFF_PROMPT_*.txt
   - Defines current scope and non-negotiables
   - First file to read in any new chat

2) docs/build_notes/PHASE*_BUILD_NOTES.txt
   - What was built and why
   - Confirms intent vs implementation

3) docs/bug_notes/PHASE*_BUG_NOTES.txt
   - Known landmines
   - Intentional compromises (if any)

4) docs/phase*/PHASE*_OPERATOR_NOTES.txt
   - How this behaves operationally
   - What an operator must NOT do

5) docs/appendices/
   - Governance, invariants, protocols (including this file)


3. ONE-COMMAND HEALTH CHECK
---------------------------
This command answers:
- Is the repo clean?
- Are tests passing?
- Is the phase stable?

Run:

    git status
    pytest -q

Interpretation:
- Any untracked files → STOP
- Any failing tests → STOP
- Green + clean → proceed


4. DIRECTORY TRUST MODEL
------------------------
Not all directories are equal. This prevents over-reading.

HIGH TRUST (authoritative):
- allmight/
- tests/
- docs/phase*/
- docs/build_notes/
- docs/bug_notes/
- docs/appendices/

MEDIUM TRUST (configuration):
- config/phase*/
- config/*

LOW TRUST (supporting, historical, or experimental):
- docs/_archive/
- docs/bugs/
- scripts/ (unless explicitly referenced by a phase handoff)

If a file is not referenced by:
- A phase handoff
- A test
- Or an appendix

…it is NOT authoritative.


5. SEARCH-FIRST RULE (ANTI-GUESSWORK)
------------------------------------
Before asking “where is X handled?” run:

    rg "X"

Examples:
- rg "allowlist"
- rg "NetworkGate"
- rg "market_snapshot_live"
- rg "phase9"

Tests are the primary source of truth.
If behavior is not asserted in tests, it is not guaranteed.


6. TESTS AS CONTRACT MAP
-----------------------
Tests answer these questions faster than prose:

- What is allowed?
- What is denied?
- What must never happen?

Priority order:
1) tests/phase*/test_*contracts*.py
2) tests/phase*/test_*boundary*.py
3) tests/phase*/test_*adapter*.py

If tests contradict documentation:
- Tests win
- Documentation must be updated


7. SAFE IGNORE LIST
-------------------
These can be ignored unless explicitly referenced:
- Legacy helpers marked as disabled
- Archived docs
- Experimental adapters not wired into broker.call
- Commented-out code blocks

Time should never be spent here without justification.


8. HANDOFF REQUIREMENT (MANDATORY)
---------------------------------
Every phase handoff MUST include a section titled:

"Rapid Orientation"

Containing:
- Current phase number
- Entry command(s)
- Primary invariant(s)
- One-line description of what this phase does

Failure to include this section is a handoff defect.


9. META-INVARIANT
-----------------
If a future operator needs to ask:
"Where should I look?"

Then this appendix or the handoff is incomplete.


END OF APPENDIX

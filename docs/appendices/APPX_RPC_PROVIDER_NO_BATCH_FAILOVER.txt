ID: APPX-RPC-NOBATCH-FAILOVER-01
Title: RPC Provider No-Batch + Failover Policy (JS Fetchers)
Applies To: scripts/data_collection/masterFetcher/* fetchers using ethers JsonRpcProvider
Status: CANONICAL
Supersedes: Implicit provider behavior (batching / single-endpoint assumptions)
Notes:
- Many free RPC tiers reject JSON-RPC batching or impose strict per-second limits.
- Ethers v6 may batch calls; this can trigger vendor errors (DRPC batch caps; Infura -32005).
- This appendix standardizes provider creation:
  1) Disable batching (batchMaxCount=1)
  2) Support multiple endpoints via <PREFIX>_RPC_URLS
  3) Retry with backoff + rotate endpoint on rate-limit patterns

ENV Contract:
- ETHEREUM_RPC_URLS="url1,url2,url3"
- ARBITRUM_RPC_URLS="url1,url2"
- OPTIMISM_RPC_URLS="url1,url2"
- BASE_RPC_URLS="url1,url2"

Operational Guidance:
- Prefer at least 2 Ethereum endpoints to reduce single-vendor outages.
- Start with concurrency=1..2 on mainnet while validating.
- Increase only after measuring error-rate and latency.

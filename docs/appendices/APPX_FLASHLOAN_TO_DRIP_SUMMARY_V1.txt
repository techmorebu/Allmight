SECTION 0 — CANONICAL PRINCIPLES (THE NON-NEGOTIABLES)
============================================================

P0. PROFITABILITY IS ABSOLUTE (FLASHLOANS)
- If the flashloan contract path is not net-profitable after worst-case gas + fees
  + slippage bounds, it must not execute.
- Flashloans do not “probe” markets.
- Flashloans do not “learn” execution behavior live.

P1. IDLE IS SUCCESS
- “No trade” is a valid, desirable state.
- The GUI must explain idling in plain language.

P2. FAIL CLOSED
- Kill conditions are authoritative.
- LIVE mode cannot bypass kills.
- No “force trade” control surface exists.

P3. VAULTS ARE NOT A BUFFET
- Bots may push value downstream into vaults.
- Bots may not pull capital upstream from vaults (except via explicitly designed,
  versioned rebalancing mechanisms).
- Realized profits only: no recognized profit until terminal collapse occurs.


============================================================
SECTION 1 — FLASHLOAN ARBITRAGE LANE (AGGRESSIVE, BUT ATOMIC)
============================================================

1.1 PURPOSE
- Use flashloans to execute leveraged arbitrages while preventing capital loss
  (atomicity is the safety feature).

1.2 EXECUTION STYLE
- Flashloan sizing should be aggressive: “max profitable” within constraints.
- Hard gates:
  - minimum net profit
  - maximum gas cost
  - profitability-to-gas ratio
  - revert budget / gas burn budgets
- If any gate fails: do not trade.

1.3 PROHIBITIONS
- No probing.
- No live learning by spending gas.
- No execution if private/MEV-protected submission is unavailable (as required by policy).

1.4 OBSERVABILITY (MUST BE VISIBLE IN UI)
- profitability gate PASS/FAIL
- estimated gas vs ceiling
- revert rate
- last decision reason


============================================================
SECTION 2 — INVENTORY ARBITRAGE (HARVEST MODEL)
============================================================

2.1 PURPOSE
- Find and execute pair opportunities across venues and routes.
- Liquidate results into a terminal asset to build vaults.

2.2 INVENTORY EXPOSURE
- Inventory exposure is allowed only as a temporary state.
- TTL is enforced.
- Forced unwind is required on TTL breach.

2.3 TERMINAL ASSET POLICY (ENFORCED)
- Arbitrage must terminate in:
  - stablecoin (default), OR
  - approved long-hold asset (policy-gated, capped)
- No “temporary holding” states.
- Profit recognized only after terminal collapse is complete.


============================================================
SECTION 3 — VAULT FLOW + ALLOCATION (POST-COLLAPSE ONLY)
============================================================

3.1 GROSS VAULT FIRST
- All realized profits flow into Gross Vault Profits (neutral aggregation).
- Allocation is applied only after collapse (no unrealized PnL games).

3.2 DEFAULT ALLOCATION (REFERENCE, TUNABLE)
- 85% → Working Capital Vault
- 10% → Ops / Safety / Gas Vault
- 5%  → Long-Hold Accumulation Vault

3.3 GOVERNANCE
- Percentages express intent; they do not override kill conditions or profitability gates.
- Changes require versioned updates and re-arming if LIVE systems are affected.


============================================================
SECTION 4 — DIRECTIONAL TRADING (MILESTONE-GATED ADD-ON)
============================================================

4.1 ACTIVATION MILESTONE
- Directional trading is disabled by default.
- Enables only when Working Capital ≥ $10,000 AND stability conditions are met.

4.2 CAPITAL BOUNDS
- Directional sub-vault target: 15% of working capital
- Hard max: 20%
- Losses are siloed within the directional sub-vault.

4.3 PROFIT FLOW (KEY DECISION)
- Directional profits flow directly into Gross Vault Profits.
- Rewards are communal; risk is isolated.

4.4 RISK LIMITS (REFERENCE)
- Max loss per trade: ~1–2% of directional sub-vault
- Max drawdown: ~20–25%
- Auto-disable on drawdown breach.
- No live resizing of directional capital; rebalancing windows only.


============================================================
SECTION 5 — GAS FUNDING (INFRASTRUCTURE, NOT OPPORTUNITY)
============================================================

5.1 DEDICATED GAS WALLET
- Separate gas wallet is mandatory.
- Funded from Ops/Safety vault only.

5.2 GAS STARVATION RULE
- If gas is below minimum reserve: no trade.
- Emergency gas boosts are allowed only from Ops/Safety vault, logged, capped.

5.3 UI REQUIREMENT
- Gas wallet balance, minimums, burn rate, and blocking status must be visible.

SECTION 7 — OFFLINE STRATEGY EVOLUTION (LEARN OFFLINE, EXECUTE LIVE)
============================================================

7.1 PIPELINE (NO SKIPS)
Idea → Offline Simulation → Shadow Mode (live data, no trades) → Promotion Review → Live (bounded)

7.2 PROMOTION LEVELS
Disabled → Shadow → Limited Live → Full Live

7.3 DEMOTION
Automatic demotion on:
- live deviation from expected behavior
- regime shift invalidation
- new failure modes

SECTION 8 — BANK/IRS-READY RECORD POSTURE (FOR FUTURE LEVERAGE)
============================================================

8.1 WHAT “BANKABLE” MEANS HERE
- Clean, boring, legible statements:
  - Profit & Loss
  - Balance Sheet
  - Cash Flow Statement
- Supporting schedules:
  - revenue by strategy category (aggregated)
  - risk/controls summary (1–2 pages)

8.2 WHY THE ARCHITECTURE HELPS
- Realized profit only (post-collapse) prevents paper-gain illusions.
- Vault segregation maps cleanly to balance sheet + cashflow.

8.3 DOCUMENT HYGIENE
- Ledger-first recordkeeping.
- No commingling.
- Retention mindset: years, not weeks.

SECTION 9 — DRIP VAULT (LIFESTYLE CASHFLOW WITHOUT SABOTAGE)
============================================================

9.1 ORIGINAL INTENT (PRESERVED)
- Convert excess success into stable weekly cashflow.
- Prevent lifestyle inflation from destabilizing execution.
- Non-execution, non-predictive, rule-based.

9.2 INTEGRATION CLARIFICATION
- “Siphon” is interpreted as downstream funding only:
  Execution → Gross Vault (post-collapse) → Allocations → Working Capital → DRIP (conditional)

- DRIP never intercepts pre-collapse profit and never competes with Ops/Gas minimums.

9.3 DRIP VAULT PANEL (READ-ONLY) — MUST EXIST IN GUI
Displays (minimum):
- DRIP enabled/paused
- Current WGI
- Active tier + payout
- Consecutive weeks at tier + upgrade requirement counter
- CPL balance vs CMR (12× tier)
- PLM eligible/locked (reason)
- Ops/Gas safety PASS/BLOCKING
- Next scheduled payout + last payout timestamp

Controls:
- None in LIVE (config-only changes require version bump + re-arming)

9.4 DRIP SCHEMA FIELDS (REFERENCE)
- drip_vault.enabled
- funding.source = working_capital_post_allocation (or gross_vault_post_collapse)
- pause_if_ops_gas_below_minimum = true
- upgrade_requires_consecutive_weeks = 2
- downgrade_on_miss = immediate
- cmr_multiplier = 12
- plm.min_sustained_weeks = 12
- plm.max_monthly_plm_cap_usd = 1300
- cannot_pull_from_execution = true
- cannot_pull_from_ops_gas = true

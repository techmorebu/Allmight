============================================================
SECTION 0 — PURPOSE & THREAT MODEL
============================================================

This guide defines the authoritative setup for an AllMight host system
and its approved remote access devices.

Remote access is designed to be:
- encrypted
- revocable
- observable
- non-authoritative by default

Operator devices are treated as UNTRUSTED by design.
Loss or compromise of any device must not endanger capital.


============================================================
SECTION 1 — OPERATOR DEVICES (ROLE DEFINITIONS)
============================================================

DEVICE A — DEDICATED ANDROID TABLET (PRIMARY COCKPIT)
-----------------------------------------------------
Purpose:
- Continuous monitoring
- System pause / re-arm (policy-gated)
- GUI visibility
- DRIP Vault visibility

Capabilities:
- Web GUI access only
- No shell
- No private keys
- No live config editing

Risk profile:
- Treated as disposable
- Compromise results in observability loss only


DEVICE B — DEDICATED ANDROID PHONE (EMERGENCY KEY)
--------------------------------------------------
Purpose:
- Emergency access when tablet unavailable
- Kill switch / SAFE_HARBOR access
- Status verification while mobile

Capabilities:
- Web GUI access
- Optional command-restricted SSH (Phase 1+)

Risk profile:
- Lowest trust
- Short session duration
- Used rarely


DEVICE C — LAPTOP (OPERATOR / DEV TERMINAL)
-------------------------------------------
Purpose:
- Code development
- Config editing
- Git commits
- Controlled ops access

Capabilities:
- Full SSH
- Git
- Offline testing
- Config-as-data control plane

Risk profile:
- Highest trust
- Still not allowed to bypass LIVE rules

============================================================
SECTION 3 — BASE SECURITY HARDENING
============================================================

3.1 FIREWALL (DEFAULT DENY)
--------------------------
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow ssh
sudo ufw enable


3.2 SSH HARDENING
----------------
Edit /etc/ssh/sshd_config:

PermitRootLogin no
PasswordAuthentication no
X11Forwarding no
AllowTcpForwarding no
ChallengeResponseAuthentication no

Restart SSH:
sudo systemctl restart ssh

SECTION 4 — TAILSCALE (REMOTE ACCESS SPINE)
============================================================

4.1 INSTALL
-----------
curl -fsSL https://tailscale.com/install.sh | sh

4.2 TAILSCALE RULES (NON-NEGOTIABLE)

- NO Funnel

Tailscale is the ONLY remote ingress path.

SECTION 8 — REMOTE ACCESS PHASES (STACKED)
============================================================

------------------------------------------------------------
PHASE 0 — OBSERVABILITY ONLY (DEFAULT)
------------------------------------------------------------

TABLET:
- Tailscale
- Single browser
- Web GUI only

PHONE:
- Tailscale
- Web GUI only

LAPTOP:
- SSH
- Git
- Offline tools

Capabilities:
- Monitor system
- Pause system
- Re-arm after policy cooldown

Prohibitions:
- No config changes
- No force trades
- No execution overrides


------------------------------------------------------------
PHASE 1 — OPERATOR CONSOLE (CONTROLLED WRITE)
------------------------------------------------------------

Enable command-restricted SSH keys.

SSH key rules:
- command-restricted
- no-pty
- no-agent-forwarding
- no shell

Allowed commands (examples):
- restart services
- rotate logs
- snapshot status
- enter SAFE_HARBOR
- trigger offline tests

Tablet:
- NO SSH

Phone:
- Optional restricted SSH (emergency only)

Laptop:
- Primary ops terminal


------------------------------------------------------------
PHASE 2 — CONFIG-AS-DATA CONTROL PLANE
------------------------------------------------------------

Model:
- Config changes are files (YAML/JSON)
- Changes committed to Git
- Host pulls only in SAFE_HARBOR
- Schema validated
- Requires re-arm ritual

Tablet & Phone:
- Read-only

Laptop:
- Edit configs
- Commit signed changes
- Trigger re-arm


------------------------------------------------------------
PHASE 3 — OFFLINE DEV / REVIEW (OPTIONAL)
------------------------------------------------------------

Tablet:
- GitHub web
- Markdown review
- Issue tracking

Phone:
- Status only

Laptop:
- Full dev environment

NO DEPLOYMENTS FROM MOBILE DEVICES.


============================================================
SECTION 9 — TABLET & PHONE HARDENING
============================================================

9.1 OS HARDENING
----------------
- Full disk encryption
- Long PIN (not biometrics alone)
- Short auto-lock timeout
- Remove email/social apps
- Separate Google account


9.2 NETWORK
-----------
- Tailscale always-on
- Device-specific ACLs
- Key expiration enabled

Treat devices like hardware tokens.


============================================================
SECTION 10 — FIRST LIVE CHECKLIST
============================================================

Before enabling LIVE:

- GUI accessible locally
- GUI accessible via tablet & phone
- System mode = SAFE_HARBOR
- Vaults empty but visible
- Gas wallet isolated
- No execution lanes enabled

Only then may execution be armed.

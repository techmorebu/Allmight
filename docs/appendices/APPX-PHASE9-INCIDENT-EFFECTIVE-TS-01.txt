ID: APPX-PHASE9-INCIDENT-EFFECTIVE-TS-01
Title: Incident Explain — Effective Timestamp + deny_code Extraction
Applies To: Phase 9 operator incident reporting (explained)
Status: CANONICAL
Supersedes: Any incident anchoring that uses backfill write-time ts_unix
Notes:
- Backfilled events use top-level ts_unix as "written to sink" time.
- Original event time is preserved at meta.raw.ts_unix.
- Backfilled DENY reason is preserved at meta.raw.deny_code (observed in sink).
- Incident explain MUST center and filter using effective_ts_unix = meta.raw.ts_unix (preferred) else top-level ts_unix.
- Deny breakdown MUST extract deny codes from meta.raw.deny_code first, with compatibility fallbacks.

Operator Impact
---------------
Without this, incident windows can be misleading: they cluster around backfill write-time and include large volumes of unrelated OK events.
With this, incident windows reflect the real operational timeline.

Verification
------------
Hermetic tests added to validate:
- effective timestamp selection logic
- deny_code extraction from meta.raw.deny_code

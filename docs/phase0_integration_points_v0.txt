PHASE 0 INTEGRATION POINTS – TRADING & INCOME ENGINE

Goal:
- Clearly mark where the future engine will plug into the existing Phase 0
  data and infrastructure.

------------------------------------------------------------
1. DATA INPUTS (READ SIDE)
------------------------------------------------------------

Later phases will read from:

- DEX/CEX data:
  - Source: master-fetcher.js + future fetcher modules in data-collection/
  - Schema: informed by outputs from universal-field-mapper.js and cross-reference-fields.js
- Macro indicators (DXY, SPX/QQQ, VIX, gold, silver, yields):
  - Source: new fetchers added to master-fetcher.js
  - Storage: Redis keys or DB/JSON files; to be defined
- Crypto prices (BTC, ETH, XRP) and on-chain metrics:
  - Source: price APIs, on-chain APIs, DEX subgraphs, etc.

Phase 0:
- Only sets up field mapping and fetcher skeletons.
- Confluence rules live in /docs and spreadsheets.

------------------------------------------------------------
2. STATE STORAGE (WRITE SIDE)
------------------------------------------------------------

Future engine state will be stored in:

- Redis (initially):
  - Keys like:
    - engine:macroRegime
    - engine:assetState:<asset>
    - engine:MCS
    - engine:vaults:<vaultName>
- Or a DB (Postgres/SQLite) in later phases.

Phase 0:
- Only master-fetcher writes test payloads to Redis (or mock).
- No persistent engine state yet; just definitions in docs.

------------------------------------------------------------
3. DASHBOARD / REMOTE CONTROL
------------------------------------------------------------

Future UI:
- FastAPI backend
- Tailscale-secured access
- Simple web dashboard (HTML/JS or React) that can display:
  - Current macro regime
  - Asset structure states
  - Current MCS
  - Vault balances (simulated or real)
  - Latest routing preset used for capital

Phase 0:
- Only documents the control logic and data it will show.
- No dashboard code required yet.

------------------------------------------------------------
4. FILES ADDED FOR THIS ENGINE SPEC
------------------------------------------------------------

- /docs/allmight_trading_engine_v1.txt
  - High-level narrative spec for macro regimes, structure brain, execution brain, MCS, presets.

- /docs/confluence_model_v0_paper.md
  - Structured tables for regimes, asset states, MCS components.

- /docs/vault_and_income_flow_v0.csv
  - CSV scaffold for vault structure, flows, and income ladder.

- /docs/capital_intake_presets_v0.txt
  - Detailed description of routing presets A/B/C.

- /docs/phase0_integration_points_v0.txt
  - This file; describes how all of the above will plug into Phase 1+ code.

------------------------------------------------------------
5. PHASE 1+ IMPLEMENTATION NOTE
------------------------------------------------------------

When coding starts:
- Step 1: Build small "MCS Calculator" module reading from:
  - macro data
  - asset structures (initially stubbed)
- Step 2: Build "Vault Engine" module that:
  - reads realized PnL and wages
  - applies routing presets
  - updates vault states
- Step 3: Connect both into the existing master-fetcher/Redis infrastructure:
  - MCS & vault states become regular, queryable datapoints for the dashboard and bots.

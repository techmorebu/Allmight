BLOCKER 2 — PID ALLOCATOR STATE IS LOST IN COMMAND SUBSTITUTION
======================================================================

Current loop:

  pid=$(a_alloc_pid)

Inside a_alloc_pid:

  c=$A_NEXTPID
  A_NEXTPID=$((A_NEXTPID+1))
  printf '%s' "$c"

Bash command substitution executes the function in a subshell. The update to
A_NEXTPID does not persist in the parent shell.

Boss reproduced the shell behavior independently:

  call 1 -> 4190000, parent next remains 4190000
  call 2 -> 4190000, parent next remains 4190000
  call 3 -> 4190000, parent next remains 4190000

Therefore all eight role allocations may reuse the same fictional PID.

That invalidates exact root identity and can collapse the synthetic topology.

REQUIRED CORRECTION

Allocate in the parent shell.

Acceptable pattern:
  a_alloc_pid sets a global/result variable, e.g. A_ALLOCATED_PID,
  then caller reads that variable without command substitution.

After world construction mechanically prove:

  FIXTURE_PID_COUNT=8
  FIXTURE_UNIQUE_PID_COUNT=8
  FIXTURE_DUPLICATE_PID_COUNT=0

and fail closed otherwise.

Each PID must still be proven:
  absent from real /proc
  not a historical governed baseline PID
  not canonical pidfile member
  not executor PID
  not executor ancestor

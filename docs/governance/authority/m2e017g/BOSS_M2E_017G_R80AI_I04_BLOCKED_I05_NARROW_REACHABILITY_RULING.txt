RULING 1 — I04 DEAD-ROLE RESURRECTION
======================================================================

I04 is BLOCKED under the current authorized seam.

Accepted source model:

  G2:
    DEAD_AT_BASELINE is assigned because present(PID) == false.

  G10:
    monotonic_check performs a later live present(PID) observation and can emit:
      G10_RESURRECTED

Required temporal condition:
  the same synthetic PID/identity must be absent at G2 and present at G10
  inside one executor invocation.

Current authorized seam does not provide a mutation point between G2 and G10.

The existing SP01 pre-revalidation hook is not an acceptable substitute:
  - it is byte-frozen for its authorized purpose;
  - it operates in the teardown/revalidation path;
  - it is not an authorized general mid-run PROC_ROOT mutation capability.

Therefore:

  I04_STATUS=BLOCKED
  I04_BLOCKING_REASON=NO_AUTHORIZED_G2_TO_G10_PROC_ROOT_MUTATION_SEAM
  I04_EXPECTED_STOP_GATE=G10_RESURRECTED
  I04_EXECUTION_CREDIT=NONE

Forbidden:
  - background watcher added solely to mutate PROC_ROOT mid-run;
  - polling helper added solely to wait for G2 then inject presence;
  - modifying executor timing;
  - stubbing or suppressing intervening gates;
  - repurposing SP01 beyond its frozen contract;
  - adding any new mutation seam merely to reach G10.

I04 remains a defined R28 certification case and an explicit unresolved
reachability blocker. Do not mark it implemented/passing.

RULING 2 — I05 IS NOT YET DECLARED UNREACHABLE
======================================================================

The ordinary construction:

  "create an alternate real governed-signature PID that is neither a baseline
   root nor frozen descendant"

is NOT valid for I05 because G8 executes first and would correctly terminate at:

  G8_SECOND_STACK

However, the source ordering suggests one narrow construction may be reachable
without defeating G8:

  CROSS-ROLE AUTHORIZED-ROOT SUBSTITUTION

Concept:

  - create a bounded, fixture-owned real process Q;
  - Q is deliberately included as a LIVE baseline root PID for role B;
  - therefore Q is potentially admissible to G8 through the executor's existing
    authorized_pid logic;
  - Q's REAL command line carries the governed signature for role A;
  - role A's expected baseline root PID is P, where Q != P;
  - when G9 scans for role A's signature, Q may be observable as a substitute;
  - if Q is not excluded by G9's root/frozen logic for that role, G9 may emit:
      G9_ROLE_SUBSTITUTED

This is only a design hypothesis until exact source predicates are proven.

CPT MUST source-prove, before encoding I05:

  1. G8 authorized_pid admits Q because Q is a live baseline root, regardless
     of which role's signature caused pgrep to discover it.

  2. G9's skip logic is role-relative such that:
       Q != expected PID P for role A
     and being a baseline root for role B does NOT globally exclude Q from the
     G9 substitution test for role A.

  3. No earlier gate rejects the cross-role fixture.

  4. The fixture does not create a second unrelated governed process that would
     trigger G8.

If all four are proven from exact bytes:

  I05_DESIGN_STATUS=BUILDABLE_NARROW_PATH

If any fail:

  I05_STATUS=BLOCKED
  I05_BLOCKING_REASON=G8_PREEMPTS_G9_OR_G9_EXCLUDES_BASELINE_ROOT
  do not invent another path without a new Boss ruling.

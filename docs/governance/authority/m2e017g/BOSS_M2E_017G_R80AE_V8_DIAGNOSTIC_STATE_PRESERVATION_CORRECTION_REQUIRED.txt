======================================================================
BLOCKER — PER-CASE EXECUTOR STATE IS NOT PRESERVED CORRECTLY
======================================================================

The runner uses one global variable:

  A_RC

a_run_executor() overwrites A_RC on every A case.

But a_preserve() is invoked only after A01, A02, A03 and A04 have all run:

  for _c in A01 A02 A03 A04; do a_preserve "$_c"; done

Inside a_preserve(), the preserved RC is emitted as:

  emit "A_${id}_RC_PRESERVED" "${A_RC:-UNKNOWN}"

At that point A_RC contains the most recent executor run's return code,
normally A04's.

Therefore the current runner can falsely label A01/A02/A03 with A04's RC.

This violates the R80AD requirement that A_RC be preserved per case.

There is a second consequence:

In a_case(), several BLOCK paths return before these fields are emitted:

  A_<id>_EXECUTOR_RESULT
  A_<id>_EXECUTOR_STOP_REASON
  A_<id>_EXECUTOR_RC
  A_<id>_STOP_GATE

For example, if BASELINE map resolution fails, the function returns before the
later scalar-emission block.

The diagnostic design was specifically intended to preserve those fields even
when a case BLOCKS.

A04 also does not currently emit the same complete RESULT / STOP_GATE /
STOP_REASON / RC quartet before its branch decisions.

======================================================================
REQUIRED CORRECTION
======================================================================

Capture executor scalar state immediately after EACH a_run_executor invocation,
before any verifier branch may return.

Use runner-owned per-case state.

Acceptable patterns include:

  - write a small per-case status file immediately after executor return; or
  - copy into case-keyed associative variables; or
  - emit the scalar fields immediately and have a_preserve copy them.

For each A01-A04, preserve independently:

  A_<id>_EXECUTOR_RC
  A_<id>_EXECUTOR_RESULT
  A_<id>_STOP_GATE
  A_<id>_EXECUTOR_STOP_REASON

Rules:

  - never reuse a later case's scalar value;
  - absent structured field must be recorded explicitly as NONE/ABSENT,
    not inherited from another case;
  - these fields must survive a verifier BLOCK;
  - a_preserve() must not depend on the current global A_RC to report an
    earlier case.

Preferred design:

  Immediately after a_run_executor:
    read RESULT / STOP_GATE / STOP_REASON from that case's A_TSV;
    store A_RC and those values into "$A_WORLD/case_status.tsv" or directly
    into "$OUT/A_<id>_diag/case_status.tsv".

Then all later BLOCK / PASS paths consume or preserve that immutable case-local
snapshot.

Apply the same mechanism to A04.

======================================================================
REMAINING BLOCKER — SAFETY_FAIL LIFETIME / RESET DEFECT
======================================================================

v20 contains a D01 runtime safety gate:

  if D01_TERM_DELIVERED_COUNT > 0:
    SAFETY_FAIL=$((SAFETY_FAIL+1))

This occurs during D01 execution.

But SAFETY_FAIL is not initialized until the later safety-surface section:

  SAFETY_FAIL=0

Consequences:

1. Under:

     set -u

   an actual nonzero TERM_DELIVERED_COUNT can reach arithmetic expansion with
   SAFETY_FAIL unset.

   The intended safety finding can therefore abort through an unbound-variable
   path instead of being cleanly preserved and packaged.

2. Even if SAFETY_FAIL happened to exist from incidental environment/global
   state, the later:

     SAFETY_FAIL=0

   resets the accumulator and can erase a safety violation found during D01.

Therefore the statement:

  "nonzero real delivery remains a safety failure"

is not yet fail-closed across the full runner lifetime.

======================================================================
REQUIRED CORRECTION
======================================================================

SAFETY_FAIL must be a single runner-lifetime accumulator.

Preferred correction:

  initialize exactly once BEFORE any numbered-case execution that can emit a
  safety finding.

For example, before A/I/D execution begins:

  SAFETY_FAIL=0

Then in the later safety-surface section:

  DO NOT reset it.

The later section may emit the preexisting count before adding scan failures,
but it must continue accumulating from the same variable.

Required invariants:

  SAFETY_FAIL_INITIALIZATION_COUNT=1
  SAFETY_FAIL_RESET_AFTER_CASE_EXECUTION=0

D01 real-delivery path:

  if TERM_DELIVERED_COUNT > 0:
    SAFETY_FAIL increments
    evidence is preserved
    later safety surface remains FAIL

Safety probes later in the runner:

  add to the same accumulator.

Final:

  SAFETY_SURFACE=PASS only if the full-lifetime SAFETY_FAIL == 0.

BLOCKER 2 — I-SLICE "INDEPENDENT VERIFIER" IS NOT INDEPENDENT
======================================================================

Current i_record():

  got = STOP_GATE from executor TSV via ag()

  ver = STOP_GATE from:
        $OUT/A_<id>_diag/case_status.tsv

But case_status.tsv is created by a_run_executor() by reading STOP_GATE from
the SAME executor TSV.

Therefore:

  executor_actual source = executor TSV
  verifier_actual source = copy of executor TSV field

This is not an independent verifier.
It is duplicated executor evidence.

R80 requires:
  fixture/input condition
  expected behavior
  executor actual
  independent verifier actual
  consistency

REQUIRED CORRECTION:

For I01/I02/I03/I06, derive verifier_actual from evidence independent of the
executor STOP_GATE field.

Examples of acceptable independent basis:

I01:
  fixture stat + synthetic baseline expectation prove:
    PID present
    observed starttime != expected starttime
    signature valid
    no reuse transition
  independent predicted gate:
    G2_IDENTITY_MISMATCH

I02:
  fixture stat proves starttime match
  fixture cmdline independently proves signature mismatch
  independent predicted gate:
    G2_SIGNATURE_MISMATCH

I03:

    same numeric PID
    S1 != S2
    post-transition identity observed before executor invocation
  independent predicted gate:
    G2_IDENTITY_MISMATCH

I06:

    governed-signature PID exists
    PID is not live baseline root
    PID is not frozen descendant
    PID is fixture-owned and admissible

    G8_SECOND_STACK

The verifier must not obtain its predicted gate from:
  STOP_GATE
  STOP_REASON
  case_status copied from STOP_GATE
  any other executor-produced terminal classification field.

The executor field and independent prediction may then be compared.

case_status.tsv remains useful as immutable executor diagnostic evidence, but
it is NOT the independent verifier.

BLOCKER 3 — EXACT PID CLEANUP IS NOT IDENTITY-REVALIDATED
======================================================================

Current cleanup gate:

  numeric I06_QPID
  /proc/I06_QPID exists
  -> kill -TERM "$I06_QPID"

That is exact-PID targeting, but exact PID alone is insufficient if the
captured process exits and the numeric PID is reused before cleanup.

The runner already treats PID reuse as a safety-critical identity problem.

REQUIRED CORRECTION:

At fixture creation, capture immutable cleanup identity evidence for Q:

  PID
  starttime
  cmdline/signature
  ownership/lineage identity sufficient to bind Q to the fixture

Immediately before the runner-owned TERM:

  re-read PID identity;
  require same captured PID;
  require same starttime;
  require expected fixture cmdline/signature;
  require bounded fixture ownership still holds.

Only if all revalidation predicates pass may the runner call:

  kill -TERM "$I06_QPID"

If process is already absent:
  no syscall
  record VANISHED/ALREADY_ABSENT fixture cleanup state.

If PID exists but identity differs or ownership is no longer proven:
  NO SIGNAL
  record FIXTURE_CLEANUP_IDENTITY_MISMATCH / BLOCK
  preserve evidence.

No kill escalation.
No pattern kill.

The safety scanner may still expect exactly one textual direct runner
kill -TERM site after this correction, provided it remains behind the complete
identity-revalidation gate.

======================================================================
DEFECT 3 — GIT CHECKOUT SAFETY PROBES FALSE-ZERO
======================================================================

First-run evidence reports:

  GIT_FIXTURE_CLONE_SITES          1
  GIT_FIXTURE_CLONE_CHECKOUT_SITES 0

But the exact reviewed runner contains an executable command:

  git -C "$W/repo" checkout --quiet --detach ...

Therefore zero is false.

Boss reproduced the cause from the archived runner bytes.

The direct grep pattern is built in a double-quoted shell string with:

  \"\$W/repo\"

The shell consumes the backslash protecting `$W`; grep ERE then receives `$W`,
where `$` is interpreted as the end-of-line anchor. The expression cannot match
the intended literal shell variable reference.

The analogous GIT_CANON_CHECKOUT probe uses the same risky construction around
$CANON and must be repaired at the same time.

This is BUG-009-class verifier imprecision.

REQUIRED CORRECTION

Use a verifier construction that mechanically matches literal source tokens
without shell/ERE ambiguity.

Preferred:
  fixed-string or awk token/command-position logic over SCAN_SRC,
  or a single-quoted ERE with a literal escaped dollar reaching grep intact.

Required known-positive controls:

  fixture clone site count      = 1
  fixture checkout site count   = 1

Required canonical negatives:

  canonical checkout/reset/clean/fetch/pull sites = 0
  canonical add/commit/push/reset/clean mutation sites = 0

The verifier must show the actual matching source lines for both positive and
negative-class audits.

Do not allow a zero canonical result to pass unless the same probe family has a
known-positive fixture checkout hit.

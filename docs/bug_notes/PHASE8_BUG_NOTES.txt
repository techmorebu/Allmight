PHASE 8 — BUG NOTES
===================

BUG-8-001: Stub routing conflicted with network default-deny proof
- Symptom:
  - Redaction test required a toxic stub result to exist even when network was disabled.
  - Network denial test required the normal snapshot path to raise when network is disabled.
- Root cause:
  - Snapshot routing initially always checked the network gate before returning any stub content.
  - Subsequent changes over-bypassed the gate (causing the network-deny test to stop raising).
- Fix:
  - Broker policy clarified:
    - `dummy_toxic` returns deterministic stub content without consulting the network gate
      (to validate redaction in a network-off environment).
    - `dummy` remains network-gated to prove default-deny behavior.

BUG-8-002: Redaction removed secrets but left 'authorization' token
- Symptom:
  - Tests detected the substring 'authorization' present after redaction.
- Root cause:
  - Original redaction preserved header name while masking value.
- Fix:
  - Rewrote redaction deterministically to ensure 'authorization' never survives in any casing.

BUG-8-003: Patch fragility due to pattern mismatches / escaping issues
- Symptom:
  - Some patch attempts failed because expected strings/regex patterns did not match file reality.
- Fix:
  - Used deterministic file rewrite / line-based rewrites for critical sections rather than brittle regex substitutions.

Residual risk / watchouts
- Redaction rules are intentionally conservative. Any future adapter surfaces must route all strings/errors
  through redaction at the boundary (broker) before trace/receipt emission.
- Do not relax NetworkGate default-deny semantics. Any Phase 9+ live read work must remain allowlist-driven and Phase 7 gated.

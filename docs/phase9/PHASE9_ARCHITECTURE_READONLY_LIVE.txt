PHASE 9 — READ-ONLY LIVE CONNECTIVITY (ARCHITECTURE-ONLY)
========================================================

Status
- This document is Phase 9 Step 1: Architecture-only (NO CODE).
- Phase 7 remains the sole execution authority.
- Phase 8 boundaries remain enforced: default-deny network, strict redaction, fail-closed gating.
- Phase 9 introduces read-only HTTP snapshot reads ONLY.
- Phase 9 MUST NOT introduce: trading, signing, fund movement, websockets, daemons, hidden retries, secret usage.

Scope (Strict)
- Allowed:
  - Read-only HTTP snapshot reads from public endpoints (no credentials).
  - Single-shot calls initiated by the operator via Phase 7 CLI pathways (batch/explain/compact/preflight).
  - Observability via receipts/traces with strict redaction.
- Forbidden:
  - Order placement
  - Account endpoints requiring signing
  - Withdrawals/transfers
  - Websockets
  - Background daemons or schedulers
  - Hidden retries or exponential backoff
  - Credential usage or secret access
  - Persistence beyond existing Phase 7 receipt/trace mechanisms

Primary design goal
- Add minimal, auditable read-only live market snapshot plumbing, while preserving:
  - Phase 7 arming ceremony and policy authority
  - Phase 8 boundary refusals and default-deny network posture
  - Idempotency-first behavior and explicit denial reasons
  - Zero accidental execution paths

Architecture overview
- Phase 7 is the only caller that may request live reads.
- Phase 7 invokes AdapterBroker for a read-only market snapshot capability.
- AdapterBroker selects a single adapter that:
  - declares the capability MARKET_DATA_HTTP_READ_LIVE
  - declares exactly which domains it can contact (no wildcards)
  - can only perform network egress through NetworkGate
- NetworkGate enforces default-deny and only allows egress when:
  - Phase 7 gating is satisfied (arming + allowlists + environment tokens)
  - the requested domain exactly matches an allowlisted domain for (adapter, capability)
  - redirects are refused unless explicitly allowlisted (default: refuse)
- SecretsBoundary must never be consulted for Phase 9 snapshot reads.
  - If a request would require credentials, it must fail immediately.

Capability definition (Phase 9)
- New capability:
  - MARKET_DATA_HTTP_READ_LIVE
- Semantics:
  - “May request a public market snapshot over HTTPS from explicitly allowlisted domains.”
  - No credentials, no signing, no account state, no orders.

Call flow (Conceptual)
1) Operator runs Phase 7 CLI command in a mode that requests live snapshot reads.
2) Phase 7 gating:
   - verifies preflight parity
   - verifies live-arming ceremony requirements
   - verifies allowlist policy authorizes MARKET_DATA_HTTP_READ_LIVE
3) Phase 7 calls AdapterBroker with:
   - capability: MARKET_DATA_HTTP_READ_LIVE
   - adapter_id: explicit (or deterministic selection, but NEVER inferred from network)
   - request: “market snapshot” (instrument(s), timestamp, etc.)
4) AdapterBroker returns the adapter handle or refuses.
5) Adapter issues an HTTP request ONLY via NetworkGate.
6) NetworkGate either:
   - allows the request (exact domain match), or
   - refuses with explicit deny classification (no network activity)
7) Response is schema-validated (strict).
8) Output is returned to Phase 7 for receipt/trace emission with strict redaction.

Network allowlist model (No wildcards)
- Allowlist entries are keyed by:
  - adapter_id
  - capability
  - domain
- Domain matching:
  - exact match only (e.g., “api.exchange.example”)
  - no wildcards (“*.example.com” forbidden)
  - no IP literals by default
- Redirects:
  - default refuse
  - if ever allowed, must be explicit per-domain and bounded (but Phase 9 default is REFUSE)

Secrets discipline (Hard rule)
- Phase 9 market snapshots must not require credentials.
- No API keys, no HMAC signing, no auth headers.
- SecretsBoundary must refuse any attempt to fetch credentials for Phase 9 live reads.
- If an adapter attempts to access secrets, it must fail closed and redact.

Failure classifications (Explicit + observable)
All failures must be:
- fail-closed (no partial success semantics)
- explicitly classified
- redacted before receipts/traces
- non-leaky: no headers, no raw bodies, no tokens, no stack traces with secrets

Classification set (initial)
- DENY_NOT_ARMED
- DENY_NOT_ALLOWLISTED_DOMAIN
- DENY_REDIRECT_REFUSED
- DENY_METHOD_NOT_ALLOWED
- TIMEOUT_CONNECT
- TIMEOUT_READ
- HTTP_STATUS_ERROR (public-safe, status only)
- SCHEMA_INVALID
- RESPONSE_TOO_LARGE
- CONTENT_TYPE_INVALID
- ADAPTER_INTERNAL_ERROR (redacted)
- NETWORK_GATE_ERROR (redacted)

Observability (Receipts/Traces)
- Must record:
  - capability used
  - adapter_id
  - allowlisted domain decision (allowed/denied)
  - timing + classification
- Must NOT record:
  - raw response bodies
  - full URLs with query params if they can encode sensitive info (default: redact query)
  - headers beyond a safe subset (default: none)
- Exception paths:
  - All exceptions must be redacted before crossing boundaries.
  - No secret-bearing values may appear in trace/receipt output.

Invariants (Non-negotiable)
- Default-deny is preserved at NetworkGate.
- No network egress occurs without Phase 7 gating.
- No “silent retries” or implicit backoff.
- No background threads, schedulers, daemons, or websocket upgrades.
- No persistence beyond existing Phase 7 trace/receipt outputs.
- No secrets are accessed, stored, or emitted.

Threat model (Read-only network threats)
Threat: SSRF-style misuse (attempt to pivot to internal resources)
- Mitigation:
  - exact-domain allowlist only
  - refuse IP literals by default
  - refuse redirects by default

Threat: Domain drift / DNS tricks / redirect chains
- Mitigation:
  - refuse redirects by default
  - exact allowlist + explicit deny classification
  - record allow/deny decision in trace with redaction

Threat: Response poisoning (malformed / oversized / unexpected types)
- Mitigation:
  - strict schema validation
  - size limits before parsing
  - content-type validation
  - fail-closed with SCHEMA_INVALID / RESPONSE_TOO_LARGE / CONTENT_TYPE_INVALID

Threat: Timeout abuse / resource pinning
- Mitigation:
  - short connect/read timeouts
  - no retries
  - fail-closed TIMEOUT_CONNECT / TIMEOUT_READ

Threat: Data exfiltration through logs/errors
- Mitigation:
  - strict redaction on all paths (success + failure)
  - never emit raw body/headers
  - classify errors without sensitive payloads

Phase 9 “Tests first” requirements (Design list, not implementation)
- Prove NetworkGate remains default-deny without Phase 7 arming.
- Prove non-allowlisted domains are refused (no network activity).
- Prove redirects are refused by default.
- Prove no retries are performed (single attempt only).
- Prove no daemons/threads/websockets are introduced by dependencies.
- Prove schema validation rejects malformed responses.
- Prove redaction applies on ALL exception paths (including adapter exceptions and NetworkGate exceptions).

Exit criteria for moving from architecture → tests
- This document is committed.
- Threat model and invariants are accepted as binding.
- Test plan is accepted as binding.
- Only then may Phase 9 proceed to “Tests first (negative cases)” implementation.

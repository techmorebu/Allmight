APPENDIX A
PHASE-0 GOVERNANCE — DETERMINISTIC INPUT & EXECUTION SAFETY


Project: AllMight
Authority Level: Phase-0 (Foundational)
Status: Mandatory / Non-Optional


----------------------------------------------------------------
PURPOSE
----------------------------------------------------------------


This appendix defines mandatory governance rules designed to prevent
silent corruption caused by terminal paste behavior, clipboard handling,
or OS-level input nondeterminism (especially under Wayland).


All downstream phases (Phase-3 and beyond) assume strict compliance
with these rules.


----------------------------------------------------------------
CORE GOVERNANCE RULE (P0-GOV-INPUT-01)
----------------------------------------------------------------


STRUCTURED INPUT MUST NOT BE PASTED DIRECTLY INTO TERMINALS.


This includes but is not limited to:
- Python code
- Configuration files
- CSV / JSON data
- Patch content
- Multi-line shell commands
- Documentation blocks intended for files


Terminal paste is classified as UNSAFE for structured content.


----------------------------------------------------------------
MANDATED SAFE METHODS
----------------------------------------------------------------


All structured input MUST be routed through one of the following methods:


1) Wayland Clipboard Routing
   - Use: wl-paste > target_file
   - Clipboard content must be inspected before execution


2) Python Writer Method (Preferred)
   - Files are written using Python only
   - Example:
       Path("file.py").write_text(content, encoding="utf-8")


These methods are deterministic, inspectable, and auditable.


----------------------------------------------------------------
PROHIBITED METHODS
----------------------------------------------------------------


The following methods are explicitly prohibited for structured input:


- Direct terminal paste (Ctrl+Shift+V, Shift+Insert, etc.)
- Shell heredocs (<<EOF)
- Multi-line shell redirection using > or >>
- Any paste-based workflow that bypasses file inspection


----------------------------------------------------------------
SCOPE OF ENFORCEMENT
----------------------------------------------------------------


This rule applies to:


- Phase-0 (Foundational)
- Phase-3 (Replay, MCS, Regime)
- Phase-4+ (Execution, Automation, Scaling)


Any output produced under violation of this rule is NON-AUTHORITATIVE.


----------------------------------------------------------------
ENFORCEMENT & CONSEQUENCES
----------------------------------------------------------------


- Violations invalidate affected outputs
- Affected phases must be re-run after correction
- Apparent success does NOT override governance violations


This rule exists to protect system integrity, not developer convenience.

Overview
Phase 7 establishes the guarded execution boundary. It consumes Phase-6 execution plans as the ONLY authority for “what to execute” and produces deterministic receipts + per-plan traces, while enforcing arming, allowlists, and idempotency.

Scope (what Phase-7 does)
- Consumes Phase-6 plans and executes ONLY what Phase-6 planned.
- Enforces plan status (e.g., SUPPRESSED must never execute).
- Enforces explicit arming ceremony for any “live” attempt.
- Produces:
  - outputs/phase7/{asof}/phase7_execution_receipts.json
  - outputs/phase7/{asof}/traces/{plan_id}.json
  - outputs/phase7/{asof}/batch_summary.json (batch mode)
- Implements idempotency-first logic and clear failure reasons (no silent retries).

Non-goals (what Phase-7 must NOT do)
- Must NOT re-derive scores, bands, confidence, suppression, or intents.
- Must NOT rebuild plans or bypass Phase-5/6 gating_chain.
- Must NOT connect to networks by default.
- Must NOT execute without explicit adapter selection and explicit arming in live mode.

Guardrails implemented (high value)
- SUPPRESSED plans:
  - Must always DENY (tests enforce).
- Live mode:
  - Requires --armed AND arming-token AND token match with ALLMIGHT_ARMING_TOKEN env var.
  - Requires adapter allowlisted in live arming policy.
- Deterministic receipts/traces:
  - Always emit structured output (even on denial).
- Idempotency-first:
  - If already FINAL for an idempotency key, block with explicit reason.
- Operator-safe defaults:
  - paper mode, prepare-only behavior unless explicitly live-armed and allowlisted.

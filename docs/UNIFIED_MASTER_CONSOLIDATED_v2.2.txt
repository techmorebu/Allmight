0) WHAT THIS FILE IS
============================================================
This file is the single “front door” to the AllMight system.

It does three jobs:
1) Declares what is authoritative (and where it lives).
2) Defines the system at a high level (what it is, how it works, why it exists).
3) Provides an index + rules so future work lands in the right place without rewrites.

It deliberately does NOT inline giant appendices. Those live as dedicated docs.
This master stays readable, navigable, and hard to corrupt.

============================================================
1) NON-NEGOTIABLES (GOVERNANCE IN 60 SECONDS)
============================================================
A) Determinism > cleverness
- Prefer replayable, hashable inputs.
- Every “decision” must be reproducible from recorded inputs + versioned code.

B) Safety > opportunity
- Trades and automations are gated.
- Shadow-mode first for anything “intelligent”.
- Kill-switches are mandatory.

C) Append-only doctrine
- “Frozen” means frozen.
- Changes happen via PATCH docs and phase deltas, never silent edits.

D) Build hygiene
- Do not commit secrets (.env is never tracked).
- Do not commit generated artifacts unless explicitly declared “canonical”.
- Prefer python-writer file creation to avoid terminal paste corruption.

3) SYSTEM PURPOSE (THE “WHY”)
============================================================
AllMight is a modular, security-first, replayable trading + capital allocation engine.

It is designed to:
- harvest asymmetric opportunities (CEX/DEX, cross-chain, structural edges)
- compound safely with explicit capital routing (vault model)
- avoid MEV-style direct competition where possible
- self-fund hardware upgrades over time
- preserve survivability (operable under degraded conditions)

============================================================

- where it pulls capital from
- where profits go
- what triggers reductions / shutdown

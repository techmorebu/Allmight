PROJECT ALLMIGHT – TRADING & INCOME ENGINE SPEC (v1 – PAPER BUILD)

Scope:
- This spec defines the paper logic for:
  - Macro Regimes
  - Structure Brain for Core 6 assets
  - Execution Brain
  - Confluence Score model
  - Capital routing presets
- No heavy code is written in Phase 0. These rules are meant to be translated
  directly into code and config in later phases (Phase 1/2).

------------------------------------------------------------
1. MACRO REGIME MODEL
------------------------------------------------------------

Regimes:
- RISK_ON
- RISK_OFF_SOFT
- RISK_OFF_STRONG
- PANIC

Inputs (to be pulled from APIs later):
- DXY (US Dollar Index)
- SPX / QQQ (US Equities indices)
- Bond yields (e.g. US 10Y)
- VIX (volatility index)
- Gold
- Silver
- BTC
- XRP / Ripple-related macro events (news / major legal updates)

Paper Rules (to refine numerically in sheet):
- RISK_ON:
  - DXY: neutral to slightly down
  - SPX/QQQ: making higher highs / above key MAs
  - Yields: stable or slowly rising
  - VIX: low / declining
  - Gold/Silver: flat or modestly up (no panic spike)
  - BTC: above key trend line / healthy structure

- RISK_OFF_SOFT:
  - DXY: rising moderately
  - SPX/QQQ: mild pullback or choppy range
  - Yields: rising or unstable
  - VIX: elevated but not spiking
  - Gold/Silver: bid but not vertical
  - BTC: choppy, wicks in both directions

- RISK_OFF_STRONG:
  - DXY: strong up trend
  - SPX/QQQ: clear downtrend or breaking key levels
  - Yields: spiking or very unstable
  - VIX: high and pushing higher
  - Gold/Silver: strong bid / impulsive moves
  - BTC: breaking key structure levels

- PANIC:
  - DXY: sharp spike or breakdown tied to crisis
  - SPX/QQQ: crash conditions (large % down days)
  - Yields: panicked repricing
  - VIX: extreme spike
  - Gold/Silver: vertical moves
  - BTC: extreme liquidation / correlation to equities
  - XRP: macro/regulatory shocks (lawsuits, settlements, bans, etc.)

Phase 0 Deliverable:
- A numeric/threshold table in the Confluence Model doc/sheet that maps:
  - ranges of each indicator → regime classification
  - Example: VIX > 30 and SPX below 200-day MA → at least RISK_OFF_STRONG.

------------------------------------------------------------
2. STRUCTURE BRAIN – CORE 6 ASSETS
------------------------------------------------------------

Core 6:
- Gold (XAU)
- Silver (XAG)
- SPX (or QQQ)
- BTC
- ETH
- XRP

States:
- ACCUMULATION
- EXPANSION
- DISTRIBUTION
- MARKDOWN

Bias:
- LONG
- SHORT
- NEUTRAL

SMC (Smart Money Concepts) elements (conceptual):
- Liquidity pools (relative highs/lows where stops reside)
- Imbalances (FVGs – fair value gaps)
- Liquidity grabs (wick above/below key highs/lows)

For each asset, Phase 0 defines:
- What price action/structure = ACCUMULATION (sideways with absorption, failed breakdowns)
- What = EXPANSION (strong impulsive trend after accumulation)
- What = DISTRIBUTION (sideways after long uptrend, failed breakouts)
- What = MARKDOWN (persistent lower lows after distribution)

Phase 0 Deliverable:
- Table per asset:
  - Condition sets for each state
  - Bias mapping:
    - e.g., ACCUMULATION -> bias LONG if macro regime is RISK_ON, else NEUTRAL
    - e.g., MARKDOWN + RISK_OFF_STRONG -> bias SHORT or stay flat

3. EXECUTION BRAIN – PROFITABILITY & VENUES
------------------------------------------------------------

Goal:
- Formalize when the engine is allowed to actually engage routes (later code).

Phase 0 rules:
- Route profitability:
  - Define “min edge after gas/fees”:
    - Example: min 0.8–1.0% net edge for pure arbitrage
    - Higher thresholds for directional trades if volatility is high.
- Slippage tolerances:
  - Max % slippage allowed per hop or per trade.
- Allowed venues for Phase 1:
  - 1–2 CEX choices (e.g., Coinbase, Kraken – final decision deferred)
  - 1–2 DEX per main chain (e.g., Uniswap v3 on Ethereum, major DEX on Base/L2)
- Allowed chains (initial set):
  - Ethereum mainnet
  - 1–2 L2s (e.g., Base, Arbitrum) – exact list refined later.

Phase 0 Deliverable:
- A table of:
  - Chain
  - DEX/CEX
  - Min edge (after gas)
  - Max size (relative to liquidity)
  - Regime-based scaling:
    - e.g., in PANIC: no new directionals, arb-only if counterparty risk is acceptable.

4. CONFLUENCE SCORE (MCS – Macro Confluence Score)
------------------------------------------------------------

Definition:
- A numeric score combining:
  - Macro regime strength
  - Asset structure states (Core 6)
  - Execution constraints

Suggested thresholds:
- MCS < 15  → No directionals, arbitrage only, reduced size
- 15 ≤ MCS < 22 → Small positions (probing size)
- MCS ≥ 22 → Full strategy activation for allowed setups

Phase 0 Deliverable:
- A simple scoring grid:
  - Example:
    - Base macro regime score: RISK_ON = +10, RISK_OFF_SOFT = +5, RISK_OFF_STRONG = 0, PANIC = -5
    - Asset structure contribution (per asset): EXPANSION in trend direction = +2, ACCUMULATION = +1, DISTRIBUTION = 0, MARKDOWN against trend = -2
    - Execution constraints (liquidity, spreads) adjust final score ±3.

5. CAPITAL ROUTING PRESETS (A, B, C)
------------------------------------------------------------

Presets (paper, to be config later):

- PRESET A – Growth:
  - 40% → arb/flashloan liquidity
  - 30% → DeFi yield
  - 20% → XRP/ISO Tier 1
  - 10% → metals

- PRESET B – Defensive:
  - 20% → arb
  - 20% → DeFi yield
  - 30% → metals
  - 20% → XRP
  - 10% → dividends

- PRESET C – XRP-Heavy:
  - 30–40% → XRP
  - Remaining → mixed between arb, metals, DeFi yield

Phase 0 Deliverable:
- A doc/section listing these presets and
  a simple rule: “Every time new capital is added, pick a preset and log allocation.”

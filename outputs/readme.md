---

README for Outputs Folder

Directory: ./outputs


---

Purpose

The ./outputs folder stores all generated schema files and reports created by the Universal Field Mapper and subsequent scripts. These files are critical for:

1. Reviewing API schemas and available fields.


2. Cross-referencing project-required fields with API-provided fields.


3. Logging progress and debugging.




---

Structure

The folder contains:

1. Schema Files:

JSON files generated by the Universal Field Mapper.

Example: uniswap-fields-2025-01-04.json.



2. Cross-Referencing Reports:

Text files detailing field matches, missing fields, and extra fields.

Example: field-matching-report.txt.





---

File Descriptions

1. Schema Files

Format: <api_name>-fields-<date>.json

Purpose: Store schema details of each API, including:

Field names.

Field types (e.g., SCALAR, OBJECT, LIST).

Metadata for introspection.


Example Content:

[
  {
    "name": "volumeUSD",
    "type": "Float",
    "kind": "SCALAR"
  },
  {
    "name": "liquidity",
    "type": "Float",
    "kind": "SCALAR"
  }
]



---

2. Cross-Referencing Reports

File Name: field-matching-report.txt

Purpose:

Compare project-required fields with fields from the schema files.

Identify missing or extra fields for each API.


Example Content:

Field Matching Report for uniswap:
  Matching Fields: volumeUSD, liquidity, token0, token1
  Missing Fields: feesUSD, tick, gasPrice
  Extra Fields: poolDayData, factory



---

Usage Instructions

1. Schema Files

Generate Schema Files:

Run the Universal Field Mapper script:

node scripts/universal-field-mapper.js

Files will appear in the ./outputs directory.


Review Schema Files:

Open the JSON files to understand the fields available in each API.



2. Cross-Referencing Reports

Generate Field Matching Report:

Run the Cross-Referencing script:

node scripts/cross-reference-fields.js


Review Report:

Open field-matching-report.txt to:

Ensure all required fields are available.

Identify missing fields that may require alternative APIs or fallback logic.





---

Best Practices

1. Organize by Date:

Schema files are generated with the current date in the filename. Keep older files for historical reference if schema updates occur.



2. Debugging:

Use schema files to debug fetchers if data is missing or malformed.

Check the report for missing fields to prioritize API integration work.



3. Archiving:

Periodically back up the ./outputs folder to maintain historical records.





---

Example Workflow

1. Run the Universal Field Mapper:

node scripts/universal-field-mapper.js


2. Open and review the generated JSON files in the ./outputs folder.


3. Create or update prioritized-fields.json based on the available fields.


4. Run the Cross-Referencing script:

node scripts/cross-reference-fields.js


5. Use the report to refine fetchers and project logic.
